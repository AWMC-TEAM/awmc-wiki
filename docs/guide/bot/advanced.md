# AWMC BOT 指令帮助

::: tip 提示
善用搜索快捷键 <kbd>/</kbd>（电脑端）或顶部搜索按钮（手机端）进行查询。
:::
::: tip 查分 QQ 绑定（qbind）
发送 `qbind 你的QQ号`，把 QQ 邮箱收到的 6 位验证码发回 Bot 即可，无需先注册论坛；已有论坛账号也可发送 `论坛绑定` 使用 OAuth。完整流程与发送限制见 [使用说明 · qbind](/guide/bot/intro#八、论坛账号绑定-qbind)。
:::

账号绑定、B50 上传、票券、PC 同步、成绩查询与群互动现已合并到同一个 QueryBot。
指令前缀由平台配置决定；下文以不带前缀为例。

::: info 版本与可用性
本页按当前源码整理，未核验生产部署；不代表所有功能均已上线。命令开放状态、价格与限制以实际部署配置及 Bot 提示为准，下文价格为源码默认值。
:::

开始前请先发送 `用户协议`，打开网页阅读并完整复制确认词。二维码相关指令支持
`SGWCMAID...`、Wahlap `img/MAID...png` 与 `req/MAID...html` 官方链接。

::: warning 票券计费与处罚
发票提交后失败默认收取 **100 BREAK** 固定罚金；提交前的二维码验证 / 余额检查失败，以及本地 API 配额拒绝，不收该罚金。发现账号仍有未使用倍率票时会拦截发票，另按未使用票券处罚规则收取 **20 BREAK**（`one_time_qrcode` 一次性二维码模式会跳过该库存检查）；上述处罚仅在余额足够时扣除，不扣成负数。不要囤票，已发票券需上机使用。
:::

::: info 商店与下线功能
商店默认单价为双倍 BREAK 卡 **300 BREAK/小时**、FREEDOM **1000 BREAK/小时**、PASS **150 BREAK/次**，管理员可调整，实际以 `商店` 显示为准；购买本身不享受 FREEDOM 免单。PASS 在 AWMC **team 本地 API 配额**耗尽时自动消耗一次放行一个请求，不适用于 public 服务端配额，也不突破小游戏奖励上限。

福利池相关的 `抽奖池` / `贡献榜`、`领取福利` / `领福利`、`贡献总榜` / `首富榜` 已临时下线；与仍可使用的 `BREAK抽奖` 不同。
:::

::: danger 批量功能风险
`mai批量编辑` / `mai全解锁` 未经测试，非常不推荐使用：上游最长可能处理约 **30 分钟**，很有可能卡死。超时或结果未确认时请先 `查进度`，确认未生效前不要重复提交。详情见[账号编辑与批量操作](/guide/bot/commands#八、账号编辑与批量操作-v2-3)。多谱面成绩编辑 / 删除仍按谱面计费，不适用整批一口价。

::: tip 快速更新与自动更新

需先 `mai绑定`；水鱼 / 落雪仅支持 OAuth 授权。快速 / 自动更新不补 FC/FS 与 PC 数据，完整更新仍需扫码。价格、间隔及开放状态以 Bot 实际配置为准，详见[快速更新与自动更新](/guide/bot/commands#quick-update)。
:::

### 1.7 AI 生图

| 命令 | 说明 |
|------|------|
| `画图 <描述>` | 根据文字生成图片；默认消耗 358 BREAK，失败会退回预扣 BREAK |
| `画图 <描述> -p` / `--reference` | 图生图模式，先发送命令，再按提示发送参考图 |
| `画图 <描述> -q auto` | 指定图片质量；当前仅支持 `auto` |

- 也可以在同一条官方 QQ 消息中 `@机器人`、附上图片并发送 `画图 <描述>`。
- 提示词最长 4000 字符；参考图默认不超过 8 MB，支持 PNG、JPEG、WebP。
- 生图前会先进行内容审核和本地敏感内容拦截；违法违规、敏感政治、未成年人色情等请求会直接拒绝，不扣 BREAK。模型服务仍会执行上游安全审核。
- 官方 QQ 图片附件会校验实际图片内容；即使 QQ CDN 返回异常的 `Content-Type`，只要图片数据有效仍可读取，图片地址安全检查仍然生效。

| 指令 | 说明 |

**选哪个**：群里直接说「`吃拉面还是米饭`」「`是去 A 还是 B`」「`吃 A 还是 B 还是 C 呢？`」
（2～4 个选项），Bot 会随机替你定一个，回复带抽中的结果与候选清单。`还是` 表示
「仍然 / 依旧」的句子不会误触发（如 `我还是不去了吧`、`天还是那么蓝`）。选项里出现
敏感词时改发不含选项原文的版本：`# 🎲 🎯 就决定是你了：第 N 个`。

需先由群管发送 `开启mai猜歌`；与其它猜歌玩法及开字母 **同群互斥**。玩法类似 Wordle：

- 发 `maidle` 开局，从全曲库（不含宴会场）出一首歌；对局中再发一次 `maidle` = 重发提示板
- 发 `猜 曲名`（也可 `猜 别名`、`猜 #ID`）作答，每次作答对比 **7 项**：版本 / 分类 / BPM / 曲师 / 紫谱定数 / 类型 / 谱师
  - 🟩 绿 = 一致；🟨 黄 = 接近（版本相邻、BPM ±10、定数 ±0.5、曲师 / 谱师有人重合）
  - ▲ / ▼ = 答案比你猜的更新 / 更高，或更旧 / 更低
- **全群共 10 次机会**，同一人两次作答至少间隔 6 秒；找不到的曲名、多义别名、已经猜过的歌不消耗次数
- 普通模式：错 6 次后提示曲名首字，只剩最后一猜时再给模糊曲绘；`maidle 困难` 没有这些提示
- 越早猜中分越高：第 1 猜 12 分 → 第 10 猜 2 分，困难模式每档 +3；猜中者另得猜对 BREAK
- 有人猜中时，其他有效作答过的玩家各得**协助奖励** 2 分 + 1 BREAK；没人猜中则不发
- 约 4 分钟无人作答自动结束并揭晓；`重置maidle` 可提前结束
:::

### 2.13 狼人杀

群内开局、群内 / 私聊双通道操作的多人狼人杀。状态只存在内存里（**Bot 重启即解散本局**），
玩法细节以 `狼人杀帮助` 的实时文案为准。

| 指令 | 说明 |
|------|------|
| `狼人杀` | 发起一局，返回游戏 ID |
| `狼人杀加入` / `狼人杀报名` | 报名（也可私聊 `加入 <游戏ID>`） |
| `狼人杀开始` / `狼人杀开局` | **发起者 / 管理员**：人数达标时提前开局 |
| `狼人杀延长` / `延长报名` / `延长` | 报名阶段延长加入窗口 30 秒（全局最多 2 次） |
| `退出狼人杀` / `退出报名` | 报名阶段退出（开局后要打完本局，别名 `不玩了`） |
| `狼人杀状态` / `狼人杀战况` | 查看阶段、存活情况与倒计时 |
| `狼人杀名单` / `狼人杀玩家` | 查看本局玩家名单 |
| `结束狼人杀` / `解散狼人杀` | **发起者 / 管理员**：强制结束本局 |
| `狼人杀帮助` / `狼人杀说明` | 查看实时玩法说明 |
| `开启狼人杀` / `关闭狼人杀` | **群管**：本群开关（与猜歌共用同一个群开关） |

**私聊动作**：`身份`（重发身份牌）、`刀 <编号>`、`查验 <编号>`、`救` / `毒 <编号>` / `不用`、
`守 <编号>`、`开枪 <编号>` / `不开枪`、`投票 <编号>` / `弃权`、`说 <内容>`；9 人以上还有警长
玩法（`上警` / `退水` / `投警 <编号>` / `警徽流 <编号>` / `撕警徽`）。

::: tip 对局规则速览
- 人数 4～16；身份按「狼 ≈ ⌊人数 / 3⌋、预言家 1、女巫 1、其余平民」推导，人数多时加入守卫、
  白痴、猎人等角色（以实时播报为准）。
- 白天分三段：**轮流发言**（每位发言人固定时长，只有当前发言人能在群里说话，`结束发言`
  可提前交棒）→ **互通交流** → **投票窗口**（群里禁言、私信投票，从进入白天起随时可投）。
- 夜间默认两段：🛡️守卫 / 🐺狼人 / 🔮预言家 同时行动，之后 🧪女巫 用药。
- 每个阶段开场有 5 秒宽容期；非当前发言人、已出局玩家在群里发言会被**撤回并扣 BREAK**
  （存活 10 / 出局 100，可通过配置调整）。
- 结算按奖池瓜分：基础奖池随人数线性增长（4 人 100，上限 600），狼人获胜整体 ×1.2，
  另有存活加成与 MVP 加成；奖励开关与参数由管理员热配置。
:::

### 2.14 投票

群管理员可在群内发起投票，结果在群管理后台的「投票结果」页查看（含条形图 / 饼图与明细）。

| 指令 | 说明 |
|------|------|
| `创建投票 <标题> <选项A/选项B/...>` | **群管**：本群多选项投票（至少 2 个选项） |
| `创建曲目投票 <标题> [候选1/候选2/...]` | **群管**：曲目投票；候选可留空 = 开放提交（回复曲名参与） |
| `创建范围投票 <标题> 难度13~14 [时长]` | **群管**：限定定数区间的选歌投票（别名 `创建定数投票`） |
| `投票 <编号> [内容]` | 参与 / 改票；不带内容时展示详情与按钮（别名 `参与投票`） |
| `投票结果 <编号>` | 查看该投票的匿名票数榜单 |
| `投票列表` | 列出进行中的投票（别名 `进行中的投票`） |
| `关闭投票 <编号>` | 提前结算（别名 `结束投票`） |

- 时长可写 `30分钟` / `2小时`，缺省 60 分钟；到点自动结算并播报结果。
- 创建 / 关闭需要**群主或群管理员**权限；插件管理员还可以把标题带上「全服」来创建**全服投票**
  （所有群可见、票数全局聚合，结算播报只发创建时所在的群）。
- 群管理后台的「投票结果」页可查看投票列表、票数图表与**管理端可见的投票明细**。

### 2.15 入群验证、自动审批与踢人（群管） {#group-moderation}

以下指令只能在群里使用，需要**群主 / 群管理员**（或在群管理后台被授权的管理）才能执行；Bot 需要先被设为本群管理员，才能审批、踢人或禁言。

#### 入群人机验证

开启后，新成员入群时 Bot 会在群里出一道题，新成员**直接在群里回复答案**即可通过；超时或答错次数用完会被移出群聊。

| 指令 | 说明 |
|------|------|
| `入群验证` / `入群验证 状态` | 查看本群验证配置（别名 `群验证` / `人机验证`） |
| `入群验证 开启` / `入群验证 关闭` | 开关本群入群验证 |
| `入群验证 题目 算术` / `入群验证 题目 验证码` | 切换题目类型：加减乘算术题，或 4 位英数验证码 |
| `入群验证 兼容模式 开启` / `关闭` | 兼容模式（默认开启）下所有平台都发纯文本题目；关闭后部分客户端可能无法答题 |

- 默认 90 秒内作答，最多 3 次机会；验证期间该成员发的其它指令不会被执行。
- 未通过时优先踢出群聊；如果 Bot 没有开通官方踢人权限（错误码 11253），会改为**禁言 30 天**，并提示管理员手动处理。

#### 入群自动审批

按关键词自动处理入群申请（匹配申请人填写的验证信息）。开启后 Bot 会在后台定时扫描待审批列表。

| 指令 | 说明 |
|------|------|
| `自动审批` / `自动审批 查看` | 查看本群自动审批配置（别名 `加群自动审批` / `入群审批设置`） |
| `自动审批 开启` / `自动审批 关闭` | 开关自动审批 |
| `自动审批 关键词 添加 <词>` | 添加放行关键词，例如 `自动审批 关键词 添加 舞萌` |
| `自动审批 关键词 删除 <词>` / `清空` / `查看` | 管理关键词列表 |
| `自动审批 严格模式 开启` / `关闭` | 严格模式：没匹配关键词的申请**自动拒绝**；温和模式（默认）：保留给管理员人工审核 |
| `自动审批 频率 <秒>` | 后台扫描间隔，默认 30 秒，可设 15～600 秒 |
| `自动审批 播报 开启` / `关闭` | 自动通过时是否在群里播报新成员 |
| `群审批` | 立即拉取一次待审批列表并按规则处理，回报通过 / 拒绝 / 挂起人数（别名 `执行群审批` / `处理入群申请`） |

#### 踢人与群黑名单

| 指令 | 说明 |
|------|------|
| `mai踢 @某人` | 把成员移出群聊（别名 `踢人` / `移出成员`；带 @ 时也可直接发 `踢 @某人`） |
| `mai踢 @某人 -b` | 移出群聊并同时加入群黑名单，之后无法再申请入群 |
| `mai拉黑 <OpenID>` | 把**已不在群里**的成员加入黑名单（别名 `拉黑` / `群黑名单`）；还在群里的请用 `mai踢 @某人 -b` |
| `mai解封 @某人` / `mai解封 <OpenID>` | 移出群黑名单（别名 `解封` / `移出黑名单`） |

::: info 不会误伤聊天
`踢` 只有在后面 @ 了成员，或写成 `踢 <OpenID>` 时才会触发；「踢我」「踢球」之类的日常聊天不会被当成指令。
官方 QQ 群的踢人 / 黑名单接口需要腾讯开通权限，未开通时踢人会自动降级为禁言 30 天。
:::
